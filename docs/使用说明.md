# 肥鱼娘完成提醒 · 使用说明

当 DSH 顶层会话完成一轮任务时，插件会：

1. **手机通知**：经你配置的通道（飞书群机器人 / ntfy / Web Push）推送一条带「肥鱼娘」形象的通知；
2. **页内动效**：DSH Web 页面里弹出肥鱼娘说「做好啦～」的动效弹窗；
3. **失败可见**：任何通道失败都不会阻塞会话，但会在设置卡里给出降级提示与诊断。

子代理（agent teams / subagent）完成的回合**不会**触发提醒，只有你直接发起的顶层会话才会。

## 1. 安装

前提：DSH ≥ 0.2.1-rc.2，web profile（本插件面向 Web GUI；移动端经 `@linxin666/dsh-remote-web-ui` 的 https 隧道访问）。

方式一（推荐）：在 DSH 里让助手执行

```
plugin_manager install_bundle（绝对路径）/Users/hexiaoying/workspace/dsh-finish-notify
```

方式二：手工安装——把 `dsh-finish-notify/` 整个目录放进 profile 的插件目录，并在 profile 的 bundle patch（`cordis.patch.yml`）中确认已有：

```yaml
- insert:
    - id: finish-notify
      name: 'dsh-fishgirl-notify'
```

本包 `package.json` **没有任何运行时依赖**（Web Push 加密用 Node 内置 `node:crypto` 实现），安装期不执行构建脚本，不需要额外 `npm install`。

安装后刷新 Web GUI，右下角会出现肥鱼娘圆形按钮（48px）——那就是设置卡入口。

## 2. 配置总览

配置有三层，后面的覆盖前面的：

1. bundle patch 里的 `config:`（见 `cordis.patch.yml`，改默认值用）；
2. 数据目录 `${DSH_PROFILE_DIR:-~/.dsh}/finish-notify/config.json`（设置卡里改配置时写入这里）；
3. 进程内默认值（`lib/config.js` 的 `DEFAULT_CONFIG`）。

非法值（区间外、格式错）会**自动回退默认值**，并在设置卡「诊断」里列出原因（`configIssues`）。

常用项：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关 |
| `notifyCompleted` | `true` | 成功（做好啦）提醒 |
| `notifyError` | `true` | 失败也提醒 |
| `notifyMaxTokens` / `notifyInterrupted` | `false` | 触顶 / 被打断提醒 |
| `pagePopupEnabled` | `true` | 页内弹窗开关 |
| `debounceMs` | `1200` | 回合结束后等多久再发（合并短回合） |
| `coalesceMs` | `5000` | 连续完成合并成「做好啦～×N」的窗口 |
| `minGapMs` | `3000` | 两条手机通知的最小间隔 |
| `quietEnabled` / `quietStart` / `quietEnd` | `false` / `23:00` / `08:00` | 静默时段（压手机通知，页内保留；支持跨零点） |
| `suppressPushWhenVisible` | `true` | 页面正开着时不发手机通知（页内弹窗照常） |
| `channelOrder` | `[feishu, ntfy, webpush]` | 手机通道优先级；失败自动降级到下一个（可加 `feishu-app`） |
| `fallbackOnFailure` | `true` | 主通道失败后是否试下一个 |
| `feishuAppEnabled` | `false` | 飞书应用机器人通道开关（见第 6 节） |
| `feishuAppReceiveIdType` | `chat_id` | 接收方类型：`chat_id` / `open_id` / `email` |
| `feishuAppReceiveId` | （空） | 接收方 ID（群 chat_id / 用户 open_id / 邮箱） |
| `feishuAppUseCard` | `true` | 应用通道发卡片（关 = 纯文本） |
| `titleCompleted` / `bodyCompletedTemplate` | `做好啦～` / `{sessionTitle} 这一轮完成啦（用时 {duration}）` | 文案模板 |
| `includeSummary` | `false` | 是否把助手最后一段话（≤120 字）放进通知摘要（隐私敏感，默认关） |
| `ntfyServer` | `https://ntfy.sh` | ntfy 服务器（可自建） |
| `pushTtlSeconds` / `pushUrgency` | `3600` / `high` | Web Push 参数 |

模板可用变量：`{sessionTitle}`（截 12 字）、`{duration}`（如「2 分 13 秒」）、`{errorCode}`（超时/限流/没权限/出错了）。未知变量原样保留。

## 3. 通道 A：飞书群机器人（鸿蒙首选）

适合：HarmonyOS NEXT（无安卓推送生态、浏览器不支持 Web Push）——飞书原生 App 有通知权限。

1. 在飞书里随便建一个只有自己的群（或拉一个小群），群设置 → 群机器人 → 添加「自定义机器人」；
2. 复制 webhook 地址（形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxx`）；（可选）开启签名校验并把 secret 一起填；
3. DSH Web → 右下角肥鱼娘按钮 → 「飞书 webhook」粘贴 → 保存；
4. 点「发条测试」，10 秒内飞书群里应出现一张蓝色测试卡片；
5. 真实任务完成时收到绿色卡片「做好啦～」，点「看肥鱼娘」按钮直接回到 DSH 页面并播放动效。

注意：

- webhook 只保存在本机 `~/.dsh/finish-notify/secrets.json`（0600 权限），日志与诊断永不出现原文；
- 卡片被群机器人拒绝（如版本不支持 interactive）会自动降级为纯文本，仍能收到提醒；
- 频率限制（429）不会重试轰炸；服务器错误（5xx）默认重试 1 次。

## 4. 通道 B：ntfy（鸿蒙经卓易通 / 安卓）

适合：鸿蒙经卓易通（卓易通）装安卓版 ntfy App，或任何安卓设备。

1. 手机装 ntfy App（ntfy.sh 官方或 F-Droid；自建服务器则装对应客户端）；
2. 设置卡 → ntfy 区 → 点「生成主题」得到 `dsh-xxxxxx`（12 位随机，只存本机，日志脱敏）；
3. 点「复制订阅链接」，在手机 ntfy App 里粘贴订阅该主题（或点「打开订阅页」跳转 ntfy.sh）；
4. 点「发条测试」选 ntfy，手机应弹通知「收到这条，就说明 ntfy 通啦」；
5. 注意 ntfy.sh 公共服务器**不鉴权**：任何知道主题名的人都能看到消息，主题名即密码，请勿外传；介意则自建 ntfy 服务器（docker 一行），把 `ntfyServer` 改成自建地址并填访问 token。

## 5. 通道 C：Web Push（Android Chrome / 桌面）

适合：Android Chrome / Edge / 桌面 Chrome（都走 FCM）。**鸿蒙 NEXT 浏览器与国内无 GMS 设备不支持**，设置卡会显示「此设备不支持」。

前提：页面必须经 **https 公网地址**访问（remote-web-ui 的 cloudflared 隧道地址即可；`http://127.0.0.1` 仅本机调试用）。

1. 手机 Chrome 打开 DSH 隧道地址；
2. 设置卡 → Web Push 区 → 「开启通知」→ 允许浏览器通知权限；
3. 订阅成功后按钮变为「关闭通知」；VAPID 公钥自动生成并保存在 `~/.dsh/finish-notify/vapid.json`；
4. 点「发条测试」选 webpush；屏幕熄灭或切后台后再跑一个任务即可验证。

技术说明：VAPID（ES256 JWT）与载荷加密（RFC 8291 aes128gcm）全部用 Node 内置 `node:crypto` 实现，零第三方依赖。FCM 不可达（无 GMS 设备）时推送会失败并记录原因（诊断可见），不会阻塞会话。410/404 会自动清理失效订阅。

## 6. 通道 D：飞书应用机器人（免建群直发）

适合：有飞书自建应用（企业自建/个人开发者均可）且不想为提醒单独建群的用户。与通道 A 互为替代，可并存（channelOrder 里都保留时按顺序取第一个可用的）。

1. 打开[飞书开放平台](https://open.feishu.cn) → 开发者后台 → 创建企业自建应用；
2. 应用能力 → 添加「机器人」能力；
3. 权限管理 → 开通 **im:message:send_as_bot**（以应用身份发消息）；版本管理与发布应用（自建应用需发布后权限才生效）；
4. 凭证与基础信息页复制 **App ID**（`cli_` 开头）与 **App Secret**；
5. 确定接收方：
   - 发到群：把应用机器人加进群（群设置 → 群机器人 → 添加本应用），接收方类型选 `chat_id`；群 chat_id 可从群设置或调试工具获取；
   - 发给个人：接收方类型选 `open_id`（通讯录接口/调试工具获取）或 `email`（用户登录邮箱，需开通通讯录只读权限）；
6. DSH Web → 右下角肥鱼娘按钮 → 展开「飞书应用机器人」区块 → 打开「启用」开关 → 填 App ID、App Secret、接收方类型与接收方 ID → 保存；
7. 点「测试应用通道」，飞书应收到蓝色测试卡片。

说明：

- `tenant_access_token` 只在内存缓存（到期前 5 分钟自动刷新），**不会写盘**；失效（错误码 99991663 / 99991661）自动重取并重试一次；
- App ID / 接收方 ID 在设置卡与诊断里只显示末 4 位，App Secret 永不回显；全部只存本机 `secrets.json`（0600）；
- 默认发 interactive 卡片（与通道 A 同款「做好啦～」卡片）；卡片被拒自动降级纯文本；
- 按钮只在有 https 公网回跳地址（隧道）时出现，本机 `127.0.0.1` 地址不会外发；
- 应用未发布/权限未开通时健康检查显示「凭据无效或应用未开通权限」——先回开放平台检查发布状态。

## 7. 页内弹窗

- 顶层会话每完成一轮，页面内肥鱼娘弹出说「做好啦～」（约 3 秒自动退场，可点击「知道了」或按 Esc / 下滑关闭）；
- 失败轮次为橙色「呜…出错了」形象；
- 点手机通知的「看肥鱼娘」按钮回到页面时，URL 带 `?finish=...`，弹窗立即播放（旧通知显示「这条提醒有点旧啦」）；
- 尊重系统「减少动态效果」（prefers-reduced-motion）：退化为静态卡片；
- 遥控手机竖屏布局（remote-web-ui）下同样可见，不遮挡输入区。

## 8. 设置卡

右下角肥鱼娘按钮打开，包含：

- **状态卡**：插件是否启用、各通道 已配置/未配置/不可达/不支持、最近一次投递结果；
- **凭证区**：飞书 webhook、飞书应用 App ID/Secret + 接收方、ntfy 主题/token（保存即写入 secrets.json，界面只显示掩码）；
- **测试区**：「发条测试」可选通道真实发送（真实发送会绕过静默/可见抑制，确保能收到）；
- **开关区**：总开关、页内弹窗、失败也提醒、页面可见时不发手机通知（即时生效，自动持久化）；
- **诊断区**：通道健康、最近投递 5 条、隧道主机名、SW scope、VAPID 指纹、配置问题、复制脱敏诊断文本。

设置卡的 HTTP 接口（`/api/finish-notify/*`）要求同源访问；本机回环（loopback）默认放行便于脚本调试（`allowLoopbackControl: false` 可关闭）。这不是安全边界——webhook 等敏感操作仍然只写本机文件。

## 9. 手机授权（含 iOS 添加到主屏幕）

**通用**：手机上用浏览器打开 remote-web-ui 的 cloudflared https 地址（扫码进入）。

**Android（Web Push）**：Chrome → 站点设置 → 通知 允许；订阅一次即可，别开「省电模式限制后台」否则 FCM 收不到。

**iOS / iPadOS（16.4+）**：iOS Safari 的 Web Push **只在「添加到主屏幕」后可用**：

1. Safari 打开 DSH 隧道地址 → 分享按钮 → 「添加到主屏幕」；
2. 从主屏幕图标进入（此时是 standalone PWA，插件已注入 manifest 与图标）；
3. 设置卡里点「开启通知」→ 允许；
4. iOS 设置 → 通知 → 找到该主屏幕 App → 允许通知。
   （iOS 由 Apple 推送而非 FCM，多数情况可用；若企业网络屏蔽则改用飞书/ntfy 通道。）

**鸿蒙 NEXT**：浏览器不支持 Web Push，请用飞书或 ntfy 通道（ntfy 安卓版经卓易通侧载）。

## 10. 真机验证

1. **本机自测**（无手机也能跑）：`node dsh-finish-notify/test/run-tests.mjs` —— 34 项断言覆盖事件过滤/去抖/静默/降级/加密/路由/应用机器人通道，全绿即基础功能正常；
2. **链路测试**：手机配好通道后，设置卡「发条测试」→ 手机 10 秒内收到；
3. **真实任务**：让 DSH 跑一个 1–2 分钟的任务，锁屏等待 → 收到绿色卡片/通知；
4. **点击回放**：点通知按钮 → 手机浏览器回到 DSH → 肥鱼娘弹窗自动播放；
5. **前台抑制**：页面保持可见再跑一轮 → 手机不通知、页内弹窗出现；
6. **静默时段**：临时把 quietStart/quietEnd 设为当前时间 → 手机不通知（页内保留）；
7. **失败路径**：故意填一个坏 webhook（如改一位字符）→ 应看到降级提示，其它通道顶上或页内照常。

验收口径：以上 2–4 必过；5–7 建议过。任何一步失败时 DSH 会话本身不受影响（事件处理全部 try/catch）。

## 11. 故障排查

| 现象 | 排查 |
| --- | --- |
| 没收到任何通知 | 设置卡看通道状态：未配置/不可达？总开关开着？静默时段撞上？页面可见抑制（`suppressPushWhenVisible`）开着？ |
| 飞书收不到 | webhook 是否被删（群里移除机器人后失效）？诊断里 feishu 是否 unreachable？卡片降级 text 后仍收不到说明 webhook 失效，重新添加 |
| 飞书应用机器人收不到 | 应用是否已**发布**且开通 im:message:send_as_bot 权限？机器人是否已加进目标群（chat_id 模式）？诊断里 feishu-app 显示「凭据无效或应用未开通权限」→ 回开放平台检查 |
| ntfy 收不到 | 手机 App 订阅的主题和设置卡里完全一致吗？公共 ntfy.sh 偶发限流，稍后再试或自建；token 填错 → unauthorized |
| Web Push 订阅按钮灰的 | 浏览器不支持（鸿蒙/部分国产浏览器）或页面非 https（127.0.0.1 除外） |
| Web Push 订阅成功但收不到 | 地址是不是 http://127.0.0.1（隧道未启用）？FCM 被网络屏蔽（无 GMS）？诊断看 webpush 健康与最近投递的 code |
| 通知点了没回页面 | clickUrl 只在隧道 https 地址下生成；127.0.0.1 地址不会发给公网通道（安全设计） |
| 弹窗不出现 | `pagePopupEnabled` 关了？页内在静默时段保留但 `enabled=false` 全关；看浏览器控制台有无 `/api/finish-notify/stream` 报错 |
| 子代理完成也弹 | 不应发生；若出现请反馈（过滤基于 parentSession/origin/delegationDepth 三级） |
| 想看底层 | 设置卡诊断区「复制诊断」→ 脱敏文本可直接贴给别人；宿主日志里搜 `[finish-notify]` |

数据目录：`${DSH_PROFILE_DIR:-~/.dsh}/finish-notify/`（secrets.json / vapid.json / subscriptions.json / config.json，全部 0600）。删掉该目录即完全重置。

## 12. 安全与隐私

- webhook / token / VAPID 私钥 / 订阅密钥只存本机数据目录（0700 目录、0600 文件、原子写入），日志、诊断、状态接口一律脱敏（只保留 host）；
- 绝不把 `127.0.0.1` 地址放进发给公网通道的按钮链接；
- 默认**不带**任务内容摘要（`includeSummary: false`），通知只含会话名/用时；
- 飞书走企业域名白名单（`*.feishu.cn` / `*.larksuite.com`），ntfy 主题为 12 位随机串；
- 插件不收集任何数据，全部出站请求只为投递通知本身。
