## 0. 设计目标与原则

### 0.1 一句话体验

> 你在电脑前干活，去倒杯水；DSH 做完了，飞书「叮」一声，卡片上是肥鱼娘举着鱼鳍说**「做好啦」**；你点「看肥鱼娘」，DSH 页面一打开她就蹦出来，摇尾巴又眨眼，3 秒内自己退场，不挡你继续干活。

### 0.2 三条原则

1. **不打扰（Calm）**：默认不弹任何权限申请、不自动播放声音、前台可见时只弹页内、连续短回合自动合并、可设静默时段。
2. **一眼懂（Glanceable）**：通知标题先说状态（做好啦 / 出错了 / 话说太满 / 被打断），肥鱼娘的可爱放在正文与图标；页内弹窗 1 秒内能读完标题与正文。
3. **可预期（Predictable）**：用户能随时在设置卡里看到「通道是否连通 / 最近一次投递 / 测试结果」，出错有明确下一步，不出现「不知道为什么不响」。

### 0.3 非目标（V1 明确不做）

- 默认不在通知/弹窗里出现对话正文、代码、文件内容（隐私）；唯一例外是用户显式开启的「附带一句摘要」，见 5.2.3。
- 不自建声音、振动（交给系统通知设置）。
- 不做聊天式多轮互动、不做宠物养成（那属于 `@linxin666/dsh-pet`，且它在手机竖屏被隐藏）。
- 不做多用户/云端账号；凭证只存本机。
- 不把「浏览器通知权限」当主路径：目标手机是 HarmonyOS NEXT，浏览器不支持 Push API；不要求用户「添加到主屏幕」才能用。
- 不自定义系统通知的排版（由飞书/ntfy/系统决定），只控制标题、正文、摘要、按钮、点击目标。

### 0.4 成功标准（可验收）

- 手机竖屏（375/390/430px）与横屏下，弹窗完整可读、可关闭，且**不遮挡输入框与发送键**。
- 从「回合结束」到飞书/ntfy 手机端收到 ≤ 5 秒（正常网络、App 在后台）。
- 点「看肥鱼娘」/ 通知到页内弹窗出现 ≤ 1.5 秒，且**首屏自动出现**，不需要二次点击。
- 弹窗完整动效 ≤ 3 秒；`prefers-reduced-motion` 下无位移/缩放动画。
- 浏览器不支持 Push、通道未配置、测试失败、隧道不可用四种情况下，界面都有可执行的中文指引。
- 设置卡 10 秒内可完成「选通道 → 填凭证 → 发测试 → 确认收到」闭环。

## 1. 名词与状态

| 名词 | 含义 |
|---|---|
| 回合（turn） | 用户发起的顶层会话的一轮完整交互，以「回合结束」为提醒触发点。 |
| 事件（event） | 一次回合完成产生的提醒数据（含状态、会话、耗时）。 |
| 通道 | 手机通知的发送路径：飞书群自定义机器人 / ntfy / 浏览器推送（Web Push，可选）；Bark 仅扩展位，V1 不实现。 |
| 系统通知 | 由飞书、ntfy 或浏览器渲染的锁屏/横幅通知；本规范主要用飞书卡片与 ntfy 通知。 |
| 首屏衔接 | 从通知点开 DSH 后，页面一加载就自动出现页内弹窗，不需要用户再点一次。 |
| 页内弹窗 | 本插件在 DSH 页面内渲染的肥鱼娘动效卡片（Toast 形态）。 |
| 补看 | 用户没点通知、之后切回页面时，为最近一次未读完成事件补弹一次。 |
| 静默时段 | 只抑制系统通知的时间段；页面在前台时页内弹窗照常。 |
| 设备 | 一个浏览器/主屏幕 App 的一次订阅（同一手机多浏览器算多台）。 |

**事件类型（`kind`，决定文案与视觉；与 t1 技术方案一致）**

| kind | 中文 | 说明 | 默认提醒 |
|---|---|---|---|
| `completed` | 做好啦 | 回合正常结束（最常见） | 手机 + 页内 |
| `error` | 出错了 | 回合以错误结束（工具/模型报错） | 手机 + 页内 |
| `max-tokens` | 话说太满 | 达到长度上限 | 页内；手机默认关 |
| `interrupted` | 被打断 | 用户主动停止/中断 | 页内；手机默认关 |
| `test` | 测试一下 | 设置卡「发条测试」 | 按所选通道真实发送 |

**投递状态（与 `kind` 正交；只影响界面提示，不新增通知类型）**

| 状态 | 含义 | 界面表现 |
|---|---|---|
| `ok` | 主通道发送成功 | 正常卡片/通知 |
| `degraded` | 主通道失败、保底成功；或全部失败 | 页内卡片底部一行小字 + 诊断入口；不重发 |
| `suppressed` | 静默时段 / 页面前台只弹页内 / 通道关闭 | 不显示「已静音」；进「最近完成」 |
| `expired` | 事件超过 10 分钟或链接过期 | 只定位会话，不重复弹 |

> 「超时」不是一种通知类型，而是投递结果（`timeout`）：没送到就不发「没送到」的通知，只在页内/诊断里说明。

## 2. 首次使用：通道配置引导（HarmonyOS 优先）

### 2.1 为什么不再以「浏览器通知授权」为主路径

目标手机是 HarmonyOS NEXT（单框架），系统浏览器不支持 Web Push（没有 `PushManager` / `Notification` 能力）。因此：

- **主路径 = 配置一个手机通道**：飞书群自定义机器人（推荐）或 ntfy；通知由飞书/ntfy App 发出，不依赖浏览器权限。
- **页内动效永远可用**：不依赖任何权限，是本插件的核心体验。
- **Web Push 降为可选增强**：只在支持 `PushManager` 的 Android Chrome / 桌面 Chrome / iOS 16.4+ 主屏幕 App 上显示。不支持时**隐藏入口**，只留一行说明，绝不给灰按钮或报错。

| 能力 | HarmonyOS NEXT 浏览器 | 飞书 App | ntfy App / 网页 | Android Chrome | iPhone 主屏幕 App |
|---|---|---|---|---|---|
| 收到手机通知 | ❌ | ✅ | ✅（App 或网页订阅） | ✅ | ✅（iOS 16.4+） |
| 需要浏览器权限弹窗 | — | 否 | 否 | 是 | 是 |
| 需要「添加到主屏幕」 | — | 否 | 否 | 否 | **是** |
| 本规范定位 | 只做页内 | **推荐** | 备选 | 可选 | 可选 |

**硬规则**

1. 首次进入 DSH、首次回合完成，都不申请任何权限、不自动弹「允许通知」。
2. 配置完成前，状态卡只显示「手机提醒未配置」+「去配置」；不显示「已开启」。
3. 每个通道都必须能「发条测试」，10 秒内给出结果；失败给下一步，不静默。
4. webhook / topic / token 不明文回显，不进诊断，不进日志。
5. 不把「仅页内」叫成「已开启手机提醒」——状态必须诚实。

### 2.2 入口与首次引导

| 入口 | 位置 | 说明 |
|---|---|---|
| A（主） | 设置 → 通知 · 肥鱼娘 → 顶部状态条「手机提醒未配置 · 去配置」 | 常驻，关闭引导后仍可进 |
| B（次） | 页内弹窗底部一行「手机也收提醒 ›」 | 只在未配置时出现，配置后隐藏 |
| C | 诊断区「配置通道」链接 | 测试失败后的下一步 |

**首次引导卡**（设置卡顶部；可「先不要」，关闭后 7 天内不自动展开）：

```
┌──────────────────────────────────────────┐
│  🐟  让肥鱼娘在手机上喊你一声？            │
│                                          │
│  回合做完时，飞书 / ntfy 会收到「做好啦」， │
│  点开就回到这里看肥鱼娘动效。              │
│  不需要开浏览器通知权限。                  │
│                                          │
│  [ 用飞书（推荐） ]   [ 用 ntfy ]          │
│  [ 浏览器推送（仅部分安卓/桌面） ]         │
│                              先不要       │
└──────────────────────────────────────────┘
```

- 先选一个主通道；保存后可再添加其他通道作为回退（多选按 `channelOrder` 顺序尝试）。
- 点击选项在卡内展开对应表单，不跳转外站，避免配置丢失。
- 「先不要」只关闭引导；页内动效照常，状态条显示「仅页内」。
- 不出现「开启通知」这种模糊按钮；按钮必须写清用哪个通道，例如「用飞书」。

### 2.3 飞书群自定义机器人（推荐，HarmonyOS 首选）

**四步，单屏可完成**

```
① 飞书里建一个只有自己的群        ② 群设置 → 群机器人 → 添加机器人
   （或选一个安静的自建群）             → 自定义机器人

③ 起名「DSH 肥鱼娘」，复制 Webhook   ④ 回到 DSH 粘贴 → 保存 → 发条测试
   https://open.feishu.cn/open-apis/bot/v2/hook/…
```

- **隐私提示（必显，12px 次要色）**：「机器人消息会发到这个群，群成员都能看到。建议用只有自己的群；默认不带对话正文，只有你打开「附带一句摘要」才会带最后一轮的自然语言摘要（≤60 字，代码/路径/密钥会省略）。」
- Webhook 输入框：密码型（可点眼睛显示），保存后只显示域名 + 末 4 位；行尾 `已保存（仅本机）`。
- 校验：必须匹配 `https://open.feishu.cn/open-apis/bot/v2/hook/…` 或 `https://open.larksuite.com/…`；不符合时行内红字，不保存。
- 飞书机器人若开了「关键词」：填 `DSH`（卡片脚注固定含 `DSH`）；**不要填「做好啦」**，否则「呜…出错了」等卡片会被飞书拒收。若开了「签名校验」：把密钥填到「签名密钥（可选）」，否则会报 19021。
- 「发条测试」→ 成功：`飞书收到啦！点开卡片看看能不能回到这里`；失败：按 2.6 表格给原因。
- 卡片长什么样、按钮写什么：见 6.2。

### 2.4 ntfy（备选）

**三步**

```
① 生成主题：dsh-<6 位随机>
   （或填自己的 ntfy 服务器）
② 手机 ntfy App / ntfy.sh 网页订阅该主题
③ 回来点「发条测试」
```

- 服务器默认 `https://ntfy.sh`；自建填 https 地址（如现有 cloudflared 域名 + 路径）。
- 主题是**密码级信息**：默认随机生成，输入框密码型，界面只显示末 4 位；提供「复制订阅链接」。公共 ntfy.sh 上知道主题的人都能订阅，主题要当密码保管。
- 手机端订阅页给「复制到剪贴板」；二维码为 P1（内容只含订阅 URL，不含 token）。
- 若手机应用商店没有 ntfy：提示「这台手机装不了 ntfy 的话，用飞书更稳」。
- 自建服务器开启鉴权时填 Token（可选）；Token 只存本机，诊断不显示。

### 2.5 Web Push（可选增强）

**显示条件（全部满足才显示入口）**：`isSecureContext && 'Notification' in window && 'PushManager' in window && 'serviceWorker' in navigator`。不满足时只显示一行：「当前浏览器不支持网页推送（HarmonyOS 常见），用飞书 / ntfy 更稳」，**不显示灰按钮**。

**权限申请时机（仅 Web Push 需要）**

| 时机 | 允许申请？ | 说明 |
|---|---|---|
| 页面加载 / 首次进入 | ❌ | 惊吓度最高，HarmonyOS 也直接不支持 |
| 首次收到回合完成 | ❌ | 只显示内联提示，用户点了才申请 |
| 点「开启浏览器推送」 | ✅ | 主入口，必须在点击手势内调用 |
| 点「重新检测」 | ✅ | 拒绝后的恢复入口 |
| 定时 / 自动重试 | ❌ | 永远不自动申请 |

**申请前的说明卡（不调用浏览器 API）**：先显示内联卡片，文案 `开启后，锁屏也能收到肥鱼娘的「做好啦」；只在这台设备生效。`，按钮 `开启浏览器推送` / `先不用`。只有用户点「开启浏览器推送」才调用 `Notification.requestPermission()`；系统弹窗的措辞由浏览器决定，插件不伪造。

**被拒后**：状态行 `浏览器通知被关闭` + 「重新检测」；Android 给「浏览器设置 → 网站设置 → 通知 → 允许」路径；桌面给地址栏站点设置路径；页内动效不受影响。

**iPhone（仅当用户确实想用 Web Push）**：iOS 16.4+，且必须「添加到主屏幕」后从图标打开。三步文案见 6.4；这是可选路径，不作为首次引导的主画面。

```
① Safari 打开 DSH          ② 点「分享」→ 添加到主屏幕      ③ 从主屏幕图标打开
┌──────────────────┐      ┌──────────────────┐          ┌──────────────────┐
│  DSH 页面         │      │  □ 添加到主屏幕   │          │  [DSH]            │
│  ⋯ 分享           │  →   │  □ 收藏           │    →     │  点图标，再开推送  │
└──────────────────┘      └──────────────────┘          └──────────────────┘
```

### 2.6 配置状态与测试失败提示

| 状态 | 设置卡表现 | 下一步 |
|---|---|---|
| 未配置 | `手机提醒未配置`，黄色点 | 「去配置」展开 2.2 |
| 已保存未验证 | 通道行 `已保存 · 未测试`，灰点 | 「发条测试」 |
| 已验证 | `已连接 · 14:32 测试成功`，绿点 | 可关闭 |
| 测试失败 | 行内红字 + 一句人话 | 「重试」/「看诊断」/「换通道」 |
| 凭证失效（401/403/410） | `机器人被移出群 / webhook 失效` | 重新复制；ntfy 检查 token |

**测试失败文案映射**

| 现象 | 界面显示（人话） | 诊断里的技术码 |
|---|---|---|
| 飞书 400 / 19001 / 19021 | `飞书不认这个 webhook，检查地址或签名密钥` | `feishu:400 code=19001` |
| 飞书 403 | `机器人被移出群了，重新添加一次` | `feishu:403` |
| ntfy 401 / 403 | `ntfy 服务器要 token，或 token 不对` | `ntfy:401` |
| 域名解析失败 | `连不上服务器，检查网络或隧道地址` | `net:dns` |
| 超时（5s） | `等太久没回应，可能是网络 / 隧道问题` | `timeout:5000` |
| 浏览器不支持 | `这个浏览器不支持网页推送` | `push:unsupported` |

- 失败不写「失败」大字；用 `没发出去` + 下一步。
- 原始错误只进诊断，且 webhook / topic / token 永远打码。
- 测试消息与真实提醒使用同一模板、同一按钮，避免「测试能收到、真的收不到」。

## 3. 端到端交互流程

### 3.1 主链路

```
DSH 顶层回合结束（completed / error / max-tokens / interrupted）
        │
        ▼
[宿主] 过滤子代理/后台 → 事件去重 → debounce 1.2s → coalesce 5s → minGap 3s
        │
        ├─ 页面可见 且 页内动效开 ──▶ SSE finish ──▶ 页内弹窗（2.8s）
        │                               └─「前台只弹页内」开：跳过手机通道
        │
        └─ 页面不可见 / 页内关 ──▶ 通道链：飞书 → ntfy → Web Push（若支持；feishu-app 预留）
                                      │
                                      ├─ 飞书卡片 / ntfy 通知
                                      │    标题「做好啦～」+ 会话 · 耗时（摘要可选）
                                      │    按钮「看肥鱼娘」/ 点击通知
                                      ▼
                            打开 returnUrl + finish=<noticeId>
                                      │
                                      ▼
                         DSH 页面加载 → 插件挂载即显示弹窗
                        （0–150ms 先出现，150–800ms 补内容）
                                      │
                                      ├─ 点「查看会话」→ 定位会话并关闭
                                      └─ 点「×」/ 下滑 / 2.8s 结束 → 关闭
```

- 飞书 / ntfy 的通知由对应 App 发出，**DSH 页面关着也能收到**；Web Push 才依赖 Service Worker。
- 页面不可见且通道全部失败：不重试轰炸，写诊断 + 下次打开显示一行「上次没发出去」（见 3.5）。
- 页内弹窗与手机通道是「同一事件的两条腿」：内容同源（同一份 notice 模板），避免两边说法不一致。

### 3.2 分支矩阵

| # | 场景 | 手机通道 | 页内弹窗 | 说明 |
|---|---|---|---|---|
| 1 | 页面前台可见、当前会话 | ❌（默认） | ✅ 立刻 | 避免在电脑前手机也响 |
| 2 | 页面前台、其他会话 | ❌ | ✅ 带会话名 | 只在页内提示 |
| 3 | 页面后台 / 锁屏 | ✅ 飞书/ntfy | 点开链接后首屏自动弹 | 「看肥鱼娘」/ 通知点击 |
| 4 | 设置面板 / 底部弹层打开 | 按页面可见处理 | ⏸ 排队，关闭后 ≤2s | 不覆盖操作层 |
| 5 | 输入框聚焦 / 软键盘 | 按页面可见处理 | ⏸ 失焦后；>20s 只进最近完成 | 不遮挡输入 |
| 6 | 静默时段 | ❌ 不响 | ✅ 前台照常 | 只静音手机，不静音页内 |
| 7 | 页内动效关闭 | ✅ 手机通道 | ❌ | 设置卡可关 |
| 8 | 所有手机通道关闭 | ❌ | ✅（仍开） | 状态卡显示「仅页内」 |
| 9 | 浏览器不支持 Push | — | ✅ | 自动隐藏入口，不报错 |
| 10 | 桌面浏览器 | 桌面系统通知（若开 Web Push） | ✅ | 同一套体验 |

### 3.3 点开通知 → 首屏动效（关键衔接）

**URL 契约（建议 t1 确认）**：发往飞书 / ntfy / Web Push 的 `returnUrl` 追加 `finish=<noticeId>`（已有 query 用 `&`，无则 `?`）。`noticeId` 使用 t1 的 `${sessionId}:${turn}`，做 URL 编码。

1. **同步读取，先出现再补内容**：插件客户端 `apply()` 挂载时立刻读 `location.search` 的 `finish`；有值就**先渲染弹窗骨架**，不等 SSE、不等 `/state`。
   - 0–150ms：卡片入场 + 头像 + 标题 `做好啦～` + 一行 `正在把结果捞上来…`（不是空白，也不是转圈超过 1s）。
   - 150–800ms：用 `/state` 的最近/待处理列表或 `/pending` 找到该 id；拿到后替换标题/正文/会话名，进入 4.4 的「说话」段。
   - >800ms：保留通用文案 `做好啦～ 结果已经出来啦`，按钮可点；不无限 loading。
2. **过期 / 找不到**：显示 `这条提醒有点旧啦` + `结果还在会话里，点开看看`，主按钮 `查看会话`；不显示错误码。
3. **绝不二次点开**：弹窗必须自动出现；按钮只负责跳会话，不能要求用户再点一次「查看」才看到动效。
4. **防重播**：读到 `finish` 后立即 `history.replaceState` 移除该参数（保留其他 query/hash），因此普通刷新不会再弹；`sessionStorage` 只用于同一次打开内的重复渲染去重。用户从飞书**再次**点卡片 = 新的一次主动打开，带 `finish` 就强制再弹一次。
5. **DSH 首屏还没就绪**：弹窗可先挂载；若 3s 内主界面仍不可用，先收成右下角小气泡「做好啦」，界面就绪后展开（不阻塞启动）。
6. **飞书内置浏览器**：检测到 `Lark` / `Feishu` UA 且 5s 内没找到 composer 时，弹窗底部加一行 `打不开？右上角 ⋯ → 在浏览器打开`；不默认假设它打不开。
7. **无 `finish` 参数**（用户直接打开 DSH）：不弹首屏；若存在 ≤10 分钟未读事件，按补看规则弹一次。
8. **同一设备多标签**：只有当前可见标签弹；其他标签收到 SSE 只入「最近完成」，避免每个标签都弹一遍。

### 3.4 合并（去抖）规则

t1 提供三个时间参数，设计上按「同一会话 → 多会话 → 全局」三层解释：

| 参数 | 默认 | 用户语言 | 行为 |
|---|---|---|---|
| `debounceMs` | 1200ms（1.2s） | 同一会话稍等一下 | 回合结束后等 1.2s 再发；期间同会话新 `turn/start` 则取消（短回合不单独提醒） |
| `coalesceMs` | 5000ms（5s） | 5 秒内的一起说 | 多个会话 / 连续完成合并为一条，`batch.count=N`；标题 `做好啦～×N`，正文 `一下子完成 {count} 轮啦` |
| `minGapMs` | 3000ms（3s） | 别连着响 | 全局两条通知最小间隔 3s；被压的并进下一条，不丢事件 |

- 合并只影响**手机通道**与页内展示条数；页内同屏最多 1 条，合并后显示一条带 `×N`。
- 合并后的按钮打开**最新一轮**会话；`batch.ids` 用于「最近完成」列表。
- 设置为 0 = 关闭该层（允许），行下提示「短回合多时会比较吵」。
- `×N` 只在 N≥2 出现；文案不写第二个「又」。

### 3.5 失败 / 中断 / 触顶 / 静默 / 仅页内 / 降级

| 场景 | 手机通道 | 页内 | 文案要点 |
|---|---|---|---|
| `completed` | ✅（页面不可见时） | ✅ | `做好啦～` + 会话 · 耗时 |
| `error` | ✅（默认开） | ✅ | `呜…出错了` / 卡住了（映射后的短原因），不责怪、不显示原始码 |
| `max-tokens` | ❌（默认关，可开） | ✅ | `话说太满啦` / 这一轮达到长度上限 |
| `interrupted` | ❌（默认关） | ✅ 低优先级 | `被打断啦` / 这一轮被中断 |
| 静默时段 | ❌ | ✅ | 不显示「已静音」；进最近完成 |
| 仅页内（通道全关） | ❌ | ✅ | 设置卡标签`仅页内`，不冒充「已开启手机提醒」 |
| 主通道失败、保底成功 | ✅（保底） | ✅ | 页内底部 `已改用 {保底通道} 通知你`，3s 消失 |
| 投递超时（5s 无响应） | ❌（未送达） | ✅ 若前台 | 页内底部 `手机通知没发出去（等太久）· 看诊断`；不重试轰炸 |
| 通道全部失败 | ❌（未送达） | ✅ 若前台 | 页内底部 `手机通知没发出去（原因）· 看诊断`；不重发 |
| 页面离线 / 隧道断 | — | ❌ | 恢复后不补发旧通知；诊断记录一条 |

- 「超时」不是通知类型，是投递结果（`timeout`）：没送到就不发「没送到」的通知。
- 所有失败文案不出现 `410 / 401 / ECONNREFUSED`；技术码只在诊断。
- 降级提示不遮挡按钮，只在卡片底部加一行 12px 小字；点击打开诊断，不自动跳转。

### 3.6 再次查看

1. 飞书卡片 / ntfy 通知仍在通知中心 → 再点一次「看肥鱼娘」→ 允许再弹（主动动作，不受「每设备一次」限制）。
2. 设置卡 →「最近完成」保留最近 5 条：状态点 + 会话名 + 相对时间 + `再看一次`；点击打开会话并重播一次弹窗。
3. 弹窗关闭后不留角标 / 悬浮球；不长期占位。
4. 「最近完成」是客户端内存态，刷新丢失；诊断区可看服务端最近投递记录。

## 4. 页内弹窗规格

### 4.1 结构（文字线框）

```
┌──────────────────────────────────────────┐  ← 卡片：圆角 16，背景 layer-2，1px 描边 l2
│ ┌──────┐   做好啦～                (×)   │  ← 标题 16/24 600；关闭热区 44×44
│ │ 肥鱼 │   DSH · 跑测试 · 2 分 14 秒      │  ← 元信息 12/18，最多 1 行
│ │ 娘   │   这一轮完成啦，去看看吧          │  ← 正文 14/22，最多 2 行
│ │      │   [ 查看会话 ]   [ 知道了 ]      │  ← 按钮高 44（触屏）/ 36（桌面）
│ └──────┘                                  │
└──────────────────────────────────────────┘
   ↑ 64×64（竖屏），气泡尾巴指向头像（8×8 三角，CSS 绘制即可）
```

- 头像在左，气泡在右；气泡尾巴指向头像，颜色与卡片表面一致。
- 卡片整体**不是**一个链接：只有按钮可点，避免误触跳转。
- 标题即状态词（做好啦～ / 呜…出错了 / 话说太满啦 / 被打断啦 / 测试一下）。
- 正文一行到两行；超长省略号截断，完整信息在会话里，不塞进弹窗。
- 元信息（会话名 · 耗时 · 补看标签）放在标题下、正文上的 12px 小字行，最多一行。
- 关闭按钮视觉尺寸 18px，热区 44×44；位置距卡片右上 4px。

### 4.2 尺寸与断点

| 场景 | 视口 | 卡片宽 | 头像一个 | 内边距 | 按钮高 | 说明 |
|---|---|---|---|---|---|---|
| 手机竖屏 | 375–430px | `min(100vw − 24, 400)`（351–400） | 64 | 12 | 44 | 默认形态 |
| 大屏手机/小平板竖屏 | 431–767px | `min(100vw − 32, 400)` | 56 | 12 | 44 | 仍居中 |
| 手机横屏 | 高 ≤ 500 且宽 > 高 | `min(100vw − 32, 360)` | 44 | 10 | 44 | 单行紧凑形态（见 4.6） |
| 桌面/平板 | ≥768px | 420 | 56 | 14 | 36（鼠标） | 居中于会话列底部 |
| 极窄/极矮 | 可用高度 < 96px | 100vw − 24 | 不显示 | 8 | 44 | 退化为单行 Toast（标题 + 关闭），不显示正文 |

- 卡片圆角 16px（`--dsw-radius-lg`），阴影用 `--dsw-elevation-prominent`，描边 `--dsw-alias-border-l2`。
- 视觉尺寸固定，不随内容撑高超过 168px；正文最多 2 行。
- 字号：标题 16px/24px、正文 14px/22px、元信息 12px/18px。**正文不得小于 14px**。

### 4.3 位置与「不遮挡」硬约束

- 水平：视口居中（桌面为会话内容列居中）；两侧至少 12px 安全边距。
- 垂直：**卡片底边始终位于输入框容器顶边上方 8px**；通过测量 composer 容器实际位置计算，不用固定 `bottom` 猜。
  - 兜底：`bottom: calc(env(safe-area-inset-bottom) + 96px)`（测不到 composer 时）。
- 安全区：尊重 `env(safe-area-inset-bottom)`；横屏尊重左右安全区（刘海/圆角）。
- 不遮挡：
  - 输入框、发送/停止按钮、附件按钮：卡片在其上方，绝不覆盖；
  - 页面顶部左侧的「小鲸鱼」悬浮按钮（remote-web-ui，34px，z-index 2147482999）：卡片在底部，不冲突；
  - 设置面板 / 底部选择器：打开时弹窗排队（见 3.2 #4），不叠加。
- 输入框从 1 行增长到 3 行时，卡片跟随上移（监听尺寸变化，最多重排到屏幕上半部；再高则切换极窄形态）。
- 卡片外层容器 `pointer-events: none`，卡片本体 `pointer-events: auto`，保证不挡住周围页面的点击。

### 4.4 分镜时间轴（自动播放，总计 2.8s ≤ 3s）

| 时间 | 画面 | 元素与参数 |
|---|---|---|
| 0–220ms | 卡片入场 | 透明度 0→1；`translateY(14px)→0`；`scale(.94)→1`；缓动 `cubic-bezier(.2,.8,.25,1)`；头像同时轻微下沉 2px 回弹 |
| 120–280ms | 气泡弹出 | 气泡 `scale(.86)→1`、透明度 0→1，160ms，延迟 80ms；尾巴同步出现 |
| 280–520ms | 打个招呼 | 头像轻跳：`translateY(0→−3px→0)`，240ms，`ease-out`；标题同时淡入 |
| 520–1500ms | 摆动 / 说话 | 头像 `rotate(−2deg ↔ 2deg)`，1.6s 一个来回，`ease-in-out`，无限交替；气泡尾随 1.5s 轻微呼吸（scale 1↔1.02） |
| 900–1020ms | 眨眼（P1，需 t3 眨眼帧） | 睁眼帧→闭眼帧 120ms→回睁眼帧；无该素材时省略，不影响完成度 |
| 1500–2500ms | 停留阅读 | 不再新增动效（避免抢注意力）；如有 `×N` 合并，数字 1 次弹跳即可 |
| 2500–2800ms | 退场 | 透明度 1→0；`translateY(0→8px)`；`scale(1→.98)`；200ms，`ease-in`；2800ms 从 DOM 移除 |

**暂停与延长**

- 悬停、键盘聚焦、手指按下时：暂停计时与循环动画；离开 600ms 后恢复剩余时长。
- 停留上限 10s：超过则淡出（信息可在「最近完成」再看）。
- 页面切到后台（`visibilitychange` 隐藏）：冻结时间轴；30s 内回来继续，超过则关闭（避免回来突然动一下）。

### 4.5 交互动效

| 操作 | 结果 |
|---|---|
| 点「查看会话」 | 切到对应会话并关闭；关闭动画 160ms |
| 点「知道了」/「×」 | 关闭；160ms 淡出 |
| 向下滑动卡片 > 24px | 跟随手指下移，松手关闭（180ms 回弹消失）；**仅触屏** |
| 按 `Esc`（桌面） | 关闭 |
| 连续 2 条事件 | 前一条先退场，新一条入场；不叠加两张卡（队列最多保留 1 条最新） |
| 测试发送 | 按所选通道**真实发送**（飞书 / ntfy）；Web Push 只发本机；结果在按钮下方显示，不自动关闭 |

关闭方式不做「左滑/右滑」，只做下滑，降低误触。

### 4.6 横屏紧凑形态

- 触发：`(orientation: landscape) and (max-height: 500px)`（手机横屏）。
- 结构：单行，头像 44 + 标题与正文（正文 1 行） + 主按钮（图标+文字或仅文字） + 关闭。
- 高度 76px，宽 ≤360px，水平居中，位于输入框上方 8px。
- 横屏软键盘打开时：直接延后（见 3.2 #5），不强行挤在中间。
- 横屏不覆盖顶部标题栏与左侧小鲸鱼按钮（卡片在下半屏）。

### 4.7 与 remote-web-ui 手机端布局的兼容（硬约束）

remote-web-ui 在「竖屏 + 粗指针 + 宽度 <1100px」时给 `<body>` 加 `dsh-remote-portrait`，并**隐藏**以下插件面：`[data-dsh-plugin="pet"]`、`task-board`、`ssh`、`skill-explorer`、`git-graph`、`usage`，以及 `_detailsCol`。同时它把底部选择器抬到 `z-index: 2147482000`，小鲸鱼按钮 `2147482999`，宠物精灵 `2147483000`。

因此本插件必须遵守：

1. **独立挂载**：弹窗与设置卡根节点挂在 `document.body`，根节点标 `data-dsh-plugin="finish-notify"`；**绝不能**嵌在 pet / task-board / `_detailsCol` 里，否则竖屏会跟着被隐藏。
2. **层级**：弹窗层 `z-index: 2147483100`（高于宠物精灵、小鲸鱼、底部选择器）；但**打开中的模态/设置层出现时排队不渲染**，不靠 z-index 硬压。
3. **触控尺寸**：所有可点元素 ≥44×44 CSS px（关闭、主/次按钮、整行可点区域）。
4. **输入字号**：弹窗正文 ≥14px；设置卡输入框沿用 16px（remote-web-ui 已禁止 iOS 聚焦缩放），不复用更小字号。
5. **安全区**：底部 `env(safe-area-inset-bottom)`、横屏左右 `env(safe-area-inset-left/right)`。
6. **不依赖 hover**：所有信息与操作在触屏上可完成；悬停只做加强。
7. **不抢焦点**：弹窗出现不聚焦、不滚动页面、不改变滚动位置。
8. **设置卡**：DSH 自动投影的 Config 表单 + 插件自绘的状态/凭证/测试卡；遵循 remote-web-ui 竖屏「设置面板纵向布局、导航横排」的既有适配，不写死宽度、不使用 hover 才出现的控件。

### 4.8 弹窗状态机

| 状态 | 进入条件 | 表现 | 离开 |
|---|---|---|---|
| `hidden` | 无事件/已关闭 | 不渲染 | 新事件 |
| `queued` | 有事件但页面状态不适合（模态/输入/隐藏） | 不渲染，缓存 1 条 | 条件解除 → `entering` |
| `loading` | 首屏带 `finish` 参数、数据未到 | 立即入场；正文「正在把结果捞上来…」 | 数据到 → `speaking`；800ms 超时 → 通用文案 |
| `entering` | 开始入场 | 0–220ms 入场动画 | 220ms → `speaking` |
| `speaking` | 气泡出现 | 摆动/眨眼/气泡 | 2500ms → `leaving`；用户关闭 → `leaving` |
| `paused` | 悬停/聚焦/触摸/页面隐藏 | 动画暂停，计时暂停 | 恢复 → `speaking` |
| `leaving` | 关闭或到时 | 160–200ms 退场 | 结束 → `hidden` |
| `suppressed` | 静默 + 无前台? / 通道关闭 | 不渲染，进最近完成 | 下一条事件 |

### 4.9 首屏衔接形态（从飞书/ntfy 点进来）

**目标**：用户点「看肥鱼娘」→ 页面打开 → 弹窗自动出现，**不需要第二次点击**；页面再慢也要在 150ms 内给反馈。

| 时间（插件挂载后） | 画面 | 说明 |
|---|---|---|
| 0–150ms | 卡片入场 + 头像 + 标题 `做好啦～` + 正文 `正在把结果捞上来…` | 不显示骨架屏/白块；不等待 composer |
| 150–800ms | 数据到达：填会话名元信息、正文、按钮 | 内容替换不引发布局跳动（固定最小高度） |
| >800ms | 保留通用文案 `做好啦～ 结果已经出来啦` + `查看会话` | 不无限 loading；按钮可用 |
| 找不到 / 过期 | `这条提醒有点旧啦` + `结果还在会话里` | 主按钮 `查看会话`；不显示错误码 |

- **位置**：composer 已存在时贴在其上方 8px；composer 未就绪时先固定在 `safe-area + 96px`，就绪后平滑上移（≤120ms），不来回跳。
- **标题/正文**：来自同一份 notice 模板；`loading` 阶段不显示摘要（避免模板未渲染时闪一次空行）。
- **总时长**：从弹窗出现到自动退场仍 ≤2.8s；数据晚到不延长到 3s 以上，但用户悬停/聚焦可暂停。
- **刷新**：读取 `finish` 后立即从地址栏移除，普通刷新不再自动弹；`sessionStorage` 只用于同一次打开内的重复渲染去重，再次点卡片带 `finish` 时强制重播。
- **首屏失败**：SSE/接口失败不影响弹窗出现；弹窗显示通用文案 +「看诊断」，不把用户卡在 loading。
- **飞书 webview**：不假设一定失败；只有 5s 内检测不到 composer 才显示「右上角 ⋯ → 在浏览器打开」的兜底。

## 5. 设置卡信息架构与字段清单

### 5.1 信息架构（手机端优先，单列）

```
设置 → 通知 · 肥鱼娘
```

- **两种渲染面**：
  - DSH 自动投影的 Config 表单（①③④⑤⑥⑦⑩）——字段顺序按上表声明；分组标题如果自动投影不支持，用行内小标题 + 8px 间距分隔。
  - 插件自绘卡（顶部状态、凭证、测试、诊断、最近完成）——Config 里没有凭证字段，必须自绘，不能只给一个裸输入框。
- V1 最低要求：顶部状态卡 + 飞书/ntfy 凭证 + 发条测试 + 诊断可见；「最近完成」可以 P1。
- 设置项即时保存（与 DSH 设置卡一致），保存后行尾 1.2s「已保存」勾；不设全局保存按钮。
- 主按钮只给两个：`去配置`（未配置时）/ `发条测试`（已配置时）；其余次级样式。
- 危险操作「重置本机订阅」只对 Web Push 有意义，放在高级区，二次确认。

|---|---|---|

### 5.3 默认值建议与理由

| 默认 | 理由 |
|---|---|
| 总开关开 | 用户装这个插件就是为了提醒；关着会以为坏了 |
| 页内动效开 | 不依赖任何权限，是最稳、最可爱的体验 |
| 页面前台只弹页内开 | 电脑前正在看时，手机不该再响；也符合「不打扰」 |
| 飞书默认开、ntfy 默认开，但都未配凭证 | 两者都需用户主动拿 webhook/topic；`isConfigured()=false` 时自动跳过，不假装已配置 |
| Web Push 默认开但只在支持时显示 | HarmonyOS 自动隐藏；Android/桌面可一键用 |
| 成功 + 失败开、触顶 + 中断关 | 中断多是用户自己按的；触顶不是失败，默认不吵 |
| 节奏 1.2s / 5s / 3s | 短回合不单独响、5 秒内合并、全局至少隔 3 秒；比单一 30s 更接近真实使用 |
| 静默默认关、推荐 23:00–08:00 | 默认开会造成「夜里没收到」的困惑；在说明文字里给推荐值 |
| 通道顺序飞书优先 | HarmonyOS 没有 Web Push；飞书是唯一稳定自带 App 的通道 |
| 测试真实发送 | 「测试能收到、真的收不到」是最伤的体验；测试必须走同一路径 |

### 5.4 顶部状态卡与诊断区

**状态卡（自绘，始终置顶）**

```
通知 · 肥鱼娘                      [ 去配置 ]
飞书 已连接 · 14:32 测试成功        ●
ntfy 未配置                        ○
浏览器推送 当前不支持（已隐藏）      —
最近一次：14:32 · 飞书 · 成功
```

- 状态词：`已连接` / `未配置` / `不可达` / `已失效` / `不支持` / `未授权`；每行都带文字，不只靠点。
- 主操作随状态变化：未配置 → `去配置`；已配置 → `发条测试`；失败 → `看诊断`。
- 点通道行展开该通道的凭证与测试，不跳页。
- Web Push 不支持时：该行只显示一行说明，不显示开关和红点。

**诊断区（折叠，内容全部脱敏）**

| 行 | 展示 | 脱敏 |
|---|---|---|
| 最近投递 | `14:32 · 飞书 · 成功` / `14:32 · ntfy · 401` | 只显示通道与结果 |
| 通道健康 | `飞书 ok · ntfy not-configured · push unsupported` | 不显示响应正文 |
| 隧道地址 | `xxx.trycloudflare.com` | 只显示主机名 |
| SW scope | `已注册（/api/finish-notify/）` | 只显示状态与 scope |
| VAPID 指纹 | `a1b2c3d4…`（仅 Web Push） | 私钥永不展示 |
| 版本 | `插件 0.1.0 · 协议 1` | — |
| 复制诊断 | 上面的 JSON | 断言不含 webhook/topic/token/订阅 endpoint 全文 |

- 错误先给一句人话，再给技术码；技术码默认折叠。
- 不提供「查看原始错误对象」，避免误带敏感字段。

### 5.5 空状态 / 错误态 / 保存反馈

| 情况 | 展示 |
|---|---|
| 刚安装、无任何通道 | 状态卡 `手机提醒未配置`；引导卡展开；副文案 `现在只有页内动效，配一个手机通道，锁屏也能收到` |
| 通道全关 | 顶部黄色提示条：`现在只有页内动效。要手机也响，配一个通道吧。` |

### 5.6 设置卡在手机端的适配

- 单列布局，行高 ≥44px，控件不并排挤压；时间选择用系统原生控件。
- 凭证输入框 16px 字号（避免 iOS 聚焦缩放），密码型，右侧眼睛按钮热区 ≥44×44。
- 诊断区折叠后只占一行，展开后允许横向滚动（最小宽度 480px）。
- 「通道顺序」在触屏上用上下箭头按钮排序（长按拖拽仅桌面增强），保证可用性。
- 「复制订阅链接」按钮在主题行下方，复制成功显示 1.5s `已复制`；二维码 P1。
- 危险按钮（重置订阅）与主按钮间距 ≥16px；危险操作二次确认。

## 6. 文案表

### 6.1 文案原则

- 可爱但不冒犯：不用「主人」「宝宝」「小笨蛋」，不评价身体、不制造焦虑、不催促（禁止「你怎么还不看」「已读不回」）。
- 状态先行：标题必须让人一眼知道发生了什么；可爱放在正文。
- 失败不责怪：失败文案写「卡住了 / 出错了」，不写「你弄错了」。
- 短：飞书卡片标题 ≤12 汉字、正文 ≤2 行；ntfy ≤80 汉字；页内正文 ≤28 汉字（详见 6.5）。
- 不夹带技术黑话：普通文案不出现 `turn/end`、`subscription`、`410`、`VAPID`；诊断区除外。
- 中文标点；「～」「！」克制使用（一条最多一个）。
- 通知与页内同源：同一事件用同一份模板，避免「飞书说成功、页面说出错」。

### 6.2 手机通知文案（三套通道）

#### A. 飞书卡片（主通道）

**卡片结构**

| 区域 | 内容 | 约束 |
|---|---|---|
| 标题（header） | `做好啦～` / `呜…出错了` / `话说太满啦` / `被打断啦` / `做好啦～×N` / `测试一下～` | ≤12 汉字；颜色只做辅助 |
| 头部色 | 成功 `green`；失败 `orange`；触顶 `yellow`；中断 `grey`；合并 `turquoise`；测试 `blue` | 文字必须自带状态，不能只靠颜色 |
| 第一行（元信息） | `{sessionTitle} · 用时 {duration}`；无标题则 `这一轮 · 用时 {duration}` | ≤30 汉字；plain_text |
| 第二行（正文） | `这一轮完成啦，点开看看结果` / 失败 `这一轮没跑完，点开看看原因` | ≤30 汉字；失败原因可附 1–4 字人话（超时/限流），不显示原始码 |
| 第三行（摘要，可选） | `刚刚说：{summary}` | ≤60 汉字；**默认关闭**（`includeSummary=false`）；只放自然语言，去代码块/路径/密钥；无摘要则整行省略 |
| 分隔线 | — | 摘要与按钮之间 |
| 按钮 | 成功/合并/中断：`看肥鱼娘`；失败：`看看原因`；触顶：`看看结果`；测试：`看肥鱼娘` | 4–5 汉字；primary |
| 脚注 | `DSH · 完成提醒 · {time}` | 12px；不含链接 |

**示例（成功）**

```
┌──────────────────────────────────────────┐
│ 做好啦～                                  │  ← 绿色 header
│ 跑测试 · 用时 2 分 14 秒                  │
│ 这一轮完成啦，点开看看结果                 │
│ ──────────────────────────────────────── │
│              [ 看肥鱼娘 ]                 │  ← 主按钮
│ DSH · 完成提醒 · 14:32                    │
└──────────────────────────────────────────┘
```

> 默认不显示摘要；开启「附带一句摘要」（`includeSummary=true`，建议默认 `false`）后，正文与分隔线之间多一行 `刚刚说：…`（≤60 字，含代码/路径/密钥整段省略）。

**规则**

- 卡片全部用 `plain_text` 展示用户内容（会话名/摘要/错误码），不要用 `lark_md` 拼用户内容，避免 `**`、链接、`@` 注入。
- 不 `@所有人`、不 `@` 具体人、不加「紧急」字样；机器人只发卡片。
- 摘要只放最后一段自然语言，最多 60 字；含代码/文件路径/疑似密钥时**整段省略**，不截一半。
- 按钮 URL = `returnUrl + finish=<noticeId>`；按钮打不开时用户仍可从飞书会话列表回到 DSH。
- 测试消息与真实消息同一卡片结构，仅标题换成 `测试一下～`、正文 `肥鱼娘在吗？点一下看看能不能回来～`。
- 飞书群如果只有自己：不额外提示；多人群：首次配置时提示「群成员可见，建议自建单人群」。

## 7. 可访问性

### 7.1 减少动效（prefers-reduced-motion）

- `@media (prefers-reduced-motion: reduce)` 时：
  - 禁用位移、缩放、旋转、弹性缓动；入场/退场只做 120ms 透明度渐变；
  - 摆动、眨眼、气泡呼吸全部停止；头像为静态定妆帧；
  - 动效总时长从 2.8s 变为「120ms 淡入 + 停留 + 120ms 淡出」，仍 ≤3s；
  - 自动消失仍生效，但悬停/聚焦暂停；读屏用户可通过「最近完成」回看。
- 设置项「减少动效」提供 `跟随系统 / 始终简化 / 不简化`，默认跟随系统；用户显式选择「不简化」时可覆盖系统设置（尊重自主选择）。
- 不做闪烁：任何闪烁 ≤3 次/秒，实际设计中不引入闪烁。

### 7.2 对比度

- 正文/标题使用 `--dsw-alias-label-primary`、`--dsw-alias-label-secondary`，深浅色主题自动切换；实测：
  - 浅色：`#0f1115` on `#ffffff` ≈ 19:1；`#61666b` on `#ffffff` ≈ 5.9:1。
  - 深色：`#f9fafb` on `#2c2c2e` ≈ 13:1；`#cfd3d6` on `#2c2c2e` ≈ 8.6:1。
- 成功绿 `#22c55e`、错误红（浅色 `#ec1313` / 深色 `#f25a5a`）只用于**图标/状态点/细描边**，不用于小号正文；状态永远同时有文字（如「出错了」），不单靠颜色。
- 飞书卡片的 header 颜色只是辅助，标题文字必须自带状态；ntfy 的 emoji tag 同理，不能替代 `Title`。
- 链接色 `--dsw-alias-link`（浅色 `#4176e6` / 深色 `#7aaaff`）；深色底不用低对比蓝，链接文字 ≥16px 或加下划线。
- 所有按钮文字对比度 ≥4.5:1；禁用态不低于 3:1 且配合「不可用」文案，不只用透明度。

### 7.3 字号与缩放

- 最小正文 14px，最小元信息 12px（仅辅助信息），标题 16px；不出现 10–11px 的正文。
- 支持 200% 页面缩放：卡片宽度随视口收缩，正文换行不裁切；不使用固定高度锁死内容（`min-height` 而非 `height`）。
- 行高 ≥1.4；中英混排不出现挤压。
- 输入框 16px（避免 iOS 聚焦缩放，与 remote-web-ui 一致）。

### 7.4 读屏与键盘

- 弹窗容器：`role="status"`、`aria-live="polite"`、`aria-atomic="true"`；只播报一次标题+正文，不播报按钮列表以外的装饰。
- 首屏 loading → 内容替换时，`aria-live` 只播报最终标题+正文一次，不播报「正在把结果捞上来」。
- 关闭按钮：`aria-label="关闭提醒"`；主按钮有明确文本（不用纯图标）。
- 不抢焦点、不自动聚焦；焦点进入卡片后暂停自动关闭；`Esc` 关闭。
- Tab 顺序：主按钮 → 次按钮 → 关闭（DOM 顺序与视觉一致）。
- 头像为装饰：`aria-hidden="true"` 或空 alt；不使用图片承载必要信息。
- 系统通知本身不可加 aria；因此标题必须自带状态语义（「做好啦～ / 呜…出错了 / 话说太满啦 / 被打断啦」）。
- 触控目标 ≥44×44，间距 ≥8px；关闭按钮热区 44×44。

### 7.5 时间与操作可调整（WCAG 2.2.1）

- 自动消失默认 2.8s（硬上限 3s），但出现以下任一情况时**不自动关闭**，改为手动关闭：
  - 用户把焦点移入卡片，或触摸/悬停卡片；
  - 用户把系统「减少动效」与插件「始终简化」同时打开时，仍按 2.8s 自动退场（仅淡入淡出）；信息可在「最近完成」回看；
  - 用户可在设置里关闭「自动消失」，改为常驻直到手动关闭。
- 「最近完成」保证任何自动消失的信息都可回看，满足「可延长/可找回」。

### 7.6 无障碍验证清单

- [ ] VoiceOver（iOS）/ TalkBack（Android）能读到标题、正文、两个按钮。
- [ ] 200% 缩放下卡片不裁切、不压住输入框。
- [ ] 减少动效下无位移/旋转，仅淡入淡出。
- [ ] 深色/浅色主题对比度达标。
- [ ] 只用键盘可关闭弹窗（Esc）与操作设置卡。

### 8.2 动画交付规格（方案 A 默认）

**方案 A（V1，静态 PNG + CSS 变换）**

- t3 只需交付 8.1 的静态图；动效由 t4 按 4.4 / 4.9 实现：
  - 入场：`translateY(14px) scale(.94) → 0, 1`，220ms；
  - 摆动：`rotate(-2deg ↔ 2deg)`，1.6s 交替；
  - 眨眼：`fishgirl-blink.png` 在 900–1020ms 替换；
  - 退场：`translateY(8px)` + 淡出，200ms；总 2.8s；
  - 首屏 loading：同一张 hero + 气泡；不新增素材。
- 优点：零依赖、体积小、reduced-motion 好处理。

**方案 B（P1，Lottie / 序列帧）**

- 画布 512×512，30fps，总时长 ≤2.8s；
- 关键帧与 4.4 对齐；循环段只有摆动（520–1500ms）；
- 提供首帧 PNG 作 reduced-motion 静态替代；
- Lottie JSON ≤200 KB，无外部图片依赖。

> t1 技术方案 §10.4 的「入场 320ms + 说话 1.2s + 停留 2s + 退场 240ms（约 3.76s）」是占位，**以本规范 2.8s 为准**；已同步给 t4。

## 11. 风险与开放问题

| # | 风险 / 问题 | 影响 | 设计侧应对 |
|---|---|---|---|
| 1 | HarmonyOS 浏览器不支持 Web Push | 浏览器通知路径不可用 | 主路径改为飞书/ntfy；Web Push 自动隐藏，不显示死按钮 |
| 2 | 飞书 webhook 是群级凭证，消息群成员可见 | 隐私 / 打扰同事 | 首次配置强提示「用只有自己的群」；默认不带对话内容；摘要需显式开启并去代码/路径 |
| 3 | 飞书卡片按钮在部分客户端/内置浏览器打不开 | 点不回来 | 5s 无 composer 给「在浏览器打开」；卡片保留会话名，用户可从 DSH 会话列表找回 |
| 4 | 飞书内置浏览器登录态/兼容性 | 页面打不开 | 兜底提示外部浏览器；不把「打开失败」写成「插件坏了」 |
| 5 | HarmonyOS 可能装不了 ntfy | 备选通道失效 | 文案直接说「用飞书更稳」；不隐藏该风险 |
| 6 | 飞书/ntfy 投递延迟（1–5s，网络差更久） | 用户以为没发 | 文案不承诺「立即」；诊断显示实际投递时间；测试可复现 |
| 7 | 机器人被移出群 / webhook 重置 | 静默失效 | 401/403/410 映射为人话；状态卡红点；测试失败给「重新复制」 |
| 8 | 前台可见时双重提醒 | 手机也响，吵 | `suppressPushWhenVisible` 扩展到所有手机通道；默认开 |
| 9 | 摘要泄露代码/密钥 | 隐私事故 | 摘要只取自然语言；含代码块/路径/疑似密钥整段省略；飞书用 plain_text |
| 10 | URL 的 `finish` 参数被客户端/中转丢弃 | 首屏退化为补看 | 无参数时仍按「最近未读 ≤10 分钟」补弹；不依赖参数才能工作 |
| 11 | 首屏动画与 DSH 启动抢资源 | 页面卡顿 | 弹窗先出现、数据后补；≤800ms 放弃等待；不阻塞主界面 |
| 12 | 多标签/多设备重复弹 | 打扰 | 同设备 sessionStorage 去重；只当前可见标签弹；多设备各自订阅 |
| 13 | 过度可爱引发反感 | 用户关掉 | 文案克制、可关闭、可只留通知、可设静默 |
| 14 | 通知大图裁切主体 | 图糊/角色缺半 | 1024×512、中心 60% 安全区；缩略图模拟检查 |
| 15 | Service Worker scope 与 remote-web-ui 冲突 | 注册失败/点击不回来 | 独立 scope `/api/finish-notify/`；诊断显示注册状态；Web Push 仅可选 |

**与 t1 v2.2 的对齐结果**（已确认，不再是待办）：

1. `finish=<noticeId>` 已加入三通道点击 URL；客户端命中 `lastNotice.id`/`/pending` 才播，播完 `replaceState` 移除；显式再点同一卡片强制重播，未命中静默忽略。
2. `pagePopupEnabled` 已新增，默认 `true`；false 时不下发 `finish`、两条回放都不播。
3. `suppressPushWhenVisible` / `quietSuppressPush` 已覆盖所有手机通道（键名保留）。
4. `channelOrder` 默认 `['feishu','ntfy','webpush','feishu-app']`；Bark 仅扩展位，V1 不实现，设置页仍可按显示名排序。
5. 仍待定：设备名来源、诊断字段细节（不影响界面结构）。

界面文案与交互已按本规范固定；上述只影响实现细节，不改变用户可见结构。

## 附录 B · 通道与平台差异矩阵

| 能力 | 飞书群机器人 | ntfy | Web Push（可选） |
|---|---|---|---|
| 目标平台 | HarmonyOS / iOS / Android / 桌面 | Android / 网页 / 部分平台 | Android Chrome / 桌面 / iOS 16.4+ 主屏幕 |
| 需要浏览器权限 | 否 | 否（网页订阅可能需通知权限） | 是 |
| 需要添加到主屏幕 | 否 | 否 | iOS 是 |
| 凭证 | Webhook（群级） | Server + Topic + 可选 Token | 浏览器订阅 + VAPID |
| 手机锁屏 | 飞书 App 通知 | ntfy App 通知 | 系统通知 |
| 大图 | 卡片可不带图（本规范不带） | `Attach`（可选） | `image`（仅 Android） |
| 按钮 | 卡片按钮 `看肥鱼娘` | `Click` / `Actions` | 点击通知 |
| 点击回页面 | 按钮 URL | `Click` URL | `data.url` |
| 典型延迟 | 1–3s | 1–3s | 1–5s（受 FCM/系统影响） |
| 失败表现 | 群内无消息；webhook 返回错误 | 通知不出现；HTTP 错误 | 无通知；`degraded` |
| 本规范定位 | **推荐（HarmonyOS）** | 备选 | 可选增强 |

**Web Push 平台差异（仅当启用时）**

| 能力 | Android Chrome | iOS 16.4+ 主屏幕 App | 桌面 Chrome/Edge |
|---|---|---|---|
| 权限申请 | 用户手势 | 用户手势（且仅主屏幕 App 内） | 用户手势 |
| 通知图标 | `icon` + 单色 `badge` | `apple-touch-icon`（180） | 系统样式 |
| 通知大图 | 支持 `image`（1024×512） | 不支持 | 不支持 |
| 动作按钮 | 支持（V1 不用） | 不支持 | 支持（V1 不用） |
| 拒绝后再次申请 | 浏览器站点设置 | 系统设置 | 站点设置 |
| 点击行为 | 打开/聚焦页面 | 打开 PWA | 打开/聚焦页面 |
| 通知分组/替换 | `tag` 支持较好 | 行为不完全可控 | 支持 |
| 锁屏显示 | 是 | 是 | 否（通知中心） |

> 设计上不依赖平台独有能力：任何通道都必须满足「标题自带状态 + 正文可独立读懂 + 点击能回到页面」。飞书/ntfy 的排版由对方 App 决定，插件只保证字段完整。
