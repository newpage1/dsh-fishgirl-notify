### 4.1 ⚠️ 发现的缺陷与修复（本任务内完成）

现象：经 cloudflared/CF 边缘隧道访问时，`/api/finish-notify/stream` 连接 open 但事件体被整体缓冲（curl 直连立刻收到 `retry:`+`hello`，经隧道 5s 零字节；JSON 类响应正常）。该缓冲行为**间歇性**（后续模拟器会话一次 ~1.5s 即达）。技术方案 §4.7 本就要求「SSE 不可用时 /pending 轮询兜底」，但 client.js 未实现，导致隧道缓冲时页内弹窗永远不出现——真机主链路缺陷。

修复（`client.js`，最小改动）：SSE open 后 3.5s 内未收到任何事件 → 自动降级为 2.5s 间隔 `/pending?since=` 轮询；任一 SSE 事件到达即停轮询。同时轮询路径与 SSE 路径共用去重（playedRef）。修复后：

- `node --check client.js` ✅
- `node test/run-tests.mjs` 27/27 ✅
- 桌面 / 移动视口 / 模拟器三环境弹窗全部出现 ✅

### 5.1 Web Push 在模拟器的结论（如实记录）

- **未完成浏览器订阅**：模拟器 Chrome 无 CDP/交互通道可请求通知权限并完成 `pushManager.subscribe`，因此未产生 FCM 订阅、未验证系统通知真实送达。
- **加密与投递链路已由离线测试证明**：`test/run-tests.mjs` 含 RFC 8291 aes128gcm 手工解密 roundtrip（HKDF 复算 CEK/nonce、pad 0x02）、VAPID ES256 签名独立验证、mock 端点 POST（headers：content-encoding/aes128gcm、ttl、urgency、vapid）、410/404 清理订阅、413 裁剪重发，27/27 通过。
- 按任务口径：FCM 真实送达记 **unverified（未尝试订阅）**，不伪造成功。
- 鸿蒙真机（HarmonyOS NEXT）浏览器不支持 Web Push，本通道仅作参考实现，主路径为飞书 + ntfy。

## 8. 鸿蒙真机验证清单（供用户几分钟完成）

### 8.1 飞书通道（主路径）

1. 手机飞书建一个只有自己的群 → 群设置 → 机器人 → 添加「自定义机器人」→ 复制 webhook（`https://open.feishu.cn/open-apis/bot/v2/hook/…`）。
2. 电脑打开 DSH Web GUI → 右下角肥鱼娘按钮 → 「飞书机器人 Webhook」粘贴 → 保存（本地 0600 存储，界面不回显）。
3. 点「发条测试」→ 飞书群应收到蓝色头卡片「测试一下～」+「打开 DSH」按钮（约 1–2 s）。
4. 锁屏，让 DSH 跑一个真实任务 → 完成时收到绿色头「做好啦～」卡片。
5. 点卡片「看肥鱼娘」→ 手机浏览器打开 GUI → 首屏自动弹出肥鱼娘动效。
6. （可选）填一个错误 webhook → 点测试 → 观察自动降级 text 消息与「已改用 ntfy 通知你」提示。

### 8.2 ntfy 通道（鸿蒙经卓易通装安卓版，或任何安卓设备）

1. 设置卡 → 「生成随机主题」→ 复制订阅链接（`https://ntfy.sh/dsh-xxxxxx`）。
2. 手机 ntfy App（卓易通安装安卓版）→ 添加主题 `dsh-xxxxxx`。
3. 点「发条测试」（ntfy）→ 手机收到「测试一下～」通知，带 fish+loudspeaker 标签。
4. 真实任务完成 → 收到「做好啦～」；点通知回到 GUI 看动效。
5. 注意：公共 ntfy.sh 不鉴权，知道主题名即可订阅；介意隐私可自建 ntfy 并把服务器地址填到配置 `ntfyServer`。

### 8.3 页内动效（任何设备打开 GUI 即生效）

- 完成回合后页面内自动弹肥鱼娘「做好啦～」弹窗（3 s 自动退场，可点「知道了」/Esc/下滑关闭；系统「减少动态效果」开启时为静态图）。
